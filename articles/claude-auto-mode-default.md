Claudeが一歩ごとに「許可しますか?」と聞かなくなったとしたら、それには理由があります。2026年10月22日、AnthropicはClaudeのウェブ、デスクトップ、モバイルアプリのセッションが、Pro、Max、Teamプランでデフォルトで自動モードから始まるようになると発表しました。8月にClaude Codeが得たのと同じデフォルトです。1つ1つの操作をあなたが承認する代わりに、別の自動チェックが承認します。この記事では、そのチェックが何を止めるのか、Anthropicが公表した数字、その正直な限界、そして手動に戻す方法を説明します。


## Anthropicが発表したこと
Anthropicは、自動モードに関する記事の上に日付入りの更新として発表しました。

![2026年10月22日の更新: 自動モードは来週から、Pro、Max、TeamプランのほとんどのClaudeアプリで、新規セッションのデフォルトとして展開されます。安全な操作は進み、リスクのある操作はブロックされ、その間Claudeは別の方法を探します。Enterpriseの管理者には先にメールが届きます。](https://systemdesignsimple.com/img/claude-auto-mode/oct-22-update.jpg)

*Anthropicの自動モード記事にある10月22日の更新。2026年11月4日に取得。*

この更新で大事な点は2つです。対象は新しいセッションであり、対象は「ほとんどの」Claudeアプリであって、すべての画面ではありません。Enterpriseの組織には、デフォルトが変わる前にメールが届きます。APIとクラウドプラットフォームは今のところオプトインのままです。

Claude Codeはその後、さらに先へ進んでいます。[権限モードのドキュメント](https://code.claude.com/docs/en/permission-modes)によると、Claude Code 2.1.283以降では、自動モードが対話型のターミナルセッションとVS Codeセッションの組み込みの開始モードになっており、プランやプロバイダーを問いません。

## チェックの仕組み
手動モードでは、Claudeはツール操作のたびに止まって、あなたに確認します。自動モードでは、[Anthropicの記事](https://claude.com/blog/auto-mode-default-in-claude-code)によると、各ツール呼び出しが「元に戻せない、破壊的、あるいは環境の外に向けた操作をブロックすることを狙った」分類器を通ります。

|  | 手動モード | 自動モード |
|---|---|---|
| 各ステップの判断 | あなたが承認か拒否をクリックする | 別の分類器が判断する |
| 安全な操作 | あなたのクリックを待つ | そのまま進む |
| リスクのある操作 | あなたのクリックを待つ | ブロックされ、Claudeはより安全な方法を探すか、あなたに尋ねる |
| Claudeが行き詰まったとき | 尋ね続ける | Claude Codeは連続3回、または1セッションで20回のブロックの後に手動へ戻る |
| 自分で固定したルール | 適用される | 適用され続ける。固定したデフォルトは変わらない |

大事なのは、モデルがあなたより慎重だということではありません。人は、確認の数が増えると読まなくなる、ということです。Anthropicのデータによると、ユーザーは権限プロンプトの97%を承認しています。承認ボタンはチェックではなく習慣になっていました。

## 変更の裏にある数字
Anthropicは、どちらの動作がテストされているかを知らない有料の開発者1,053人を対象にした統制実験を行いました。

![Anthropicのグラフ: 有料のプロのテスター1,053人を対象にした統制実験で、人による確認は危険なコマンドの13.6%を止め、自動モードは89%を止めました](https://systemdesignsimple.com/img/claude-auto-mode/89-vs-13.jpg)

*Anthropicの自動モード記事のグラフ。2026年11月4日に取得。*

- **89%対13.6%:** 自動モードは危険なコマンドの89%を止めました。人による確認は13.6%でした。
- **800対6:** 自動モードは、人間が承認したコマンドのうち800件をブロックしました。人間がブロックしたもののうち、自動モードが通したのは6件でした。
- **実際のセッション:** フラグが立った重大度の高いケースでは、手動で承認されたセッションの6.3%に求められていない有害な操作が含まれていました。自動モードでは2.4%でした。
- **プロンプトインジェクション:** 720回の攻撃試行の評価では、自動モードで動くClaude Fable 5、Opus 5、Sonnet 5に対して成功したものは1件もありませんでした。

これらはAnthropic自身が報告した数字です。私たちは再現していません。

## 自動モードが約束しないこと
Anthropicはここでは慎重です。あなたもそうあるべきです。外部企業とのレッドチームテストにより、合成攻撃に対する分類器の見逃し率は12%から7%に下がりました。記事によると、その7%は「実際のトラフィックにおける見逃し率として受け取るべきではありません」。つまり、疲れた人間よりミスは少ない、ゼロではない、ということです。

正しい考え方はこうです。自動モードも、プロンプトをすべて承認することも、保証ではありません。だから証拠が大事です。何かが終わったとClaudeが言う前に、コマンドとその出力、あるいはスクリーンショットを見せてもらってください。

## 手動に戻す方法、モードを固定する方法
- **セッションごと:** いつでも手動に戻せます。Claude CodeのCLIでは`Shift`+`Tab`を押して権限モードを切り替えます。デスクトップアプリでは、プロンプト欄の下にあるモード選択を使います([権限モードのドキュメント](https://code.claude.com/docs/en/permission-modes))。
- **自分のルールが優先されます:** 拒否ルールや設定で固定したものは、新しいデフォルトで変わりません。絶対に実行してはいけないコマンドがあるなら、拒否ルールを残してください。
- **チームの場合:** 管理者は、管理設定の`permissions.defaultMode`で組織全体のデフォルトを設定できます。`permissions.disableAutoMode`を`"disable"`に設定すれば、自動モードをオフにできます。
- **スクリプトの場合:** ヘッドレス実行では`--permission-mode`でモードを明示的に選びます。デフォルトに頼らず、意図して設定してください。

同じアプリでの関連する変更が2つあります。[Claude Duet](https://systemdesignsimple.com/claude-duet-proactive-agent/)では、Claudeが先にあなたへメッセージを送りますが、行動の前にはやはり確認します。[Claudeの自己評価](https://systemdesignsimple.com/claude-self-assessment/)では、Claudeが自分の会話の中で考えられる誤用を報告します。

## 私たちの正直な評価
**本当に良い点。** この変更は、人が実際にどう動くかに合っています。97%承認するプロンプトは、あなたを守っていません。危険な3%を一貫して止めるチェックのほうが守ります。固定したルールをそのままにし、Claudeが行き詰まったら手動に戻し、Enterpriseの管理者には先に警告する。これらは正しい細部です。

**気をつける点。** デフォルトは、新しいユーザーが学ばないことを変えます。自動モードから始めた人は、Claudeが実際に何を実行しているかを見ないかもしれません。だから、コマンドと出力を見せる習慣をつけてください。そして「ほとんどのClaudeアプリ」というのは、しばらくの間、画面によって動作が違う可能性があるという意味です。大事なことに触れるセッションの前には、モード表示を確認してください。

**私たちがやったこと。** 私たちは、このチャンネルの動画を作るのに毎日Claude Codeを使っています。絶対に起きてはいけないことについては、モードではなく拒否ルールとフックに頼っています。Anthropicが勧めるのと同じやり方です。分類器そのものを私たちが測ったわけではありません。

**結論:** 数字に裏づけられた、筋の通ったデフォルトです。日常の作業ではオンのままにし、絶対に壊してはいけないものには拒否ルールを残し、「終わった」と言われたら証拠を求めてください。

私たちが使っているフルセットアップ(権限、フック、ヘッドレス実行)は[プロのようにClaudeを使う方法](https://systemdesignsimple.com/claude-like-a-pro/)にあります。
