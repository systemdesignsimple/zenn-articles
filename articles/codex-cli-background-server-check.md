本記事は System Design Simple の英語記事の日本語版です。原文: https://systemdesignsimple.com/codex-cli-background-server-check/

はい、Codex CLIはターミナルを閉じたあともプロセスを残すことがあります。バージョン0.157.0から、対象の対話セッションは共有のバックグラウンドサーバーを自動で起動します。止めるコマンドは1つです。`codex features disable daemon_auto_start`。

この記事は、ターミナルでCodex CLIをほぼ毎日使う人のためのものです。とくに、共有のビルドマシンや、バックグラウンドのプロセスとディスク容量が気になるノートパソコンを使っている人です。日常の問題はシンプルです。ターミナルを閉じれば、すべて止まったと思うでしょう。2026年9月25日から、CLIはサーバーを動かしたままにし、そのパッケージをディスクに置いたままにすることがあります。私たちのMacでは338 MBでした。聞かれることはありません。下の3つのチェックで、自分のマシンが何をしているかが見えます。1つのコマンドで、自分の望む動作を選べます。

何も壊れてはいません。サーバーを起動するのは意図した動作です。問うべきは、自分のマシンでそれをオンにしておきたいかどうかだけです。バックグラウンドサーバーがあれば、複数のセッションが1つの接続を共有し、復旧も速くなります。それでも、聞かれずに起動します。私たちは5分かけて、自分のMacで何をするのか、ディスクをどれだけ使うのか、どうやって止めるのかを確かめました。手順は下の通りです。

## Codex CLI 0.157.0で何が変わったか

2026年9月25日に公開された[0.157.0のリリースノート](https://github.com/openai/codex/releases/tag/rust-v0.157.0)には、はっきり書かれています。「対象の対話セッションについて、バックグラウンドサーバーの自動起動を有効化しました。サーバー設定に互換性がない場合の復旧方法も用意しています」。その背後にあるプルリクエストのタイトルは「デフォルトで自動デーモン起動を有効化」です。

0.157.0より前は、共有のバックグラウンドサーバーはオプトインで、自動起動は実験的な設定でした。0.157.0からは、対話セッションがバックグラウンドで小さなサーバーを起動し、あとのセッションはそのサーバーと話します。

`codex exec`のような非対話の実行は、別の経路です。私たちの自動化は1日に何度も`codex exec`を呼びますが、このMacでは、その呼び出しのあいだにバックグラウンドサーバーが動いていることはありませんでした。

![バックグラウンドサーバーの自動起動をオンにしたCodex CLI 0.157.0のリリースノート(GitHub、2026年11月7日に取得)。](https://systemdesignsimple.com/img/posts/codex-cli-background-server-check/release-note.webp)
*バックグラウンドサーバーの自動起動をオンにしたCodex CLI 0.157.0のリリースノート(GitHub、2026年11月7日に取得)。*

## チェック1: 機能はオンになっているか

```sh
codex features list | grep daemon_auto_start
```

2026年11月7日、私たちのMacで、Codex CLI 0.164.0を使ったとき、このコマンドはこう表示しました。

```text
daemon_auto_start                        stable             true
```

`stable`は機能の段階、`true`は実際の状態です。つまり自動起動はオンで、これが既定です。

## チェック2: ディスクをどれだけ使うか

サーバーは、Codexフォルダの中に自分専用のパッケージとして入っています。

```sh
du -sh ~/.codex/packages/app-server-daemon/releases
```

私たちの結果は**338 MB**で、フォルダは1つだけ、`0.164.0-aarch64-apple-darwin`という名前でした。私たちのMacには0.164.0のフォルダが1つだけありました。あなたの数字はバージョンによって変わります。[Codex CLI 0.164.0](https://github.com/openai/codex/releases/tag/rust-v0.164.0)からは、CLIは使われていないサーバーのリリースを整理し、現在と直前のものを残すので、アップグレードのあとにフォルダが2つあっても普通です。

## チェック3: いま動いているか

```sh
pgrep -fl codex
```

何も表示されなければ、Codexのプロセスは動いていません。すべてのターミナルを閉じたあとにサーバーのプロセスが見えたら、バックグラウンドサーバーはまだ生きています。プロセス管理ツールから閉じることもできますし、下の方法で機能を止めて、新しいターミナルを開くこともできます。

## Codex CLIのバックグラウンドサーバーを止めるには

```sh
codex features disable daemon_auto_start
codex features list | grep daemon_auto_start
```

[`codex features disable`](https://learn.chatgpt.com/docs/developer-commands?surface=cli)は変更を`~/.codex/config.toml`に書き込むので、すべての新しいセッションに適用されます。あとで元に戻すには、`codex features enable daemon_auto_start`を実行します。

1回だけサーバーを抜きにしたい場合は、[Codex CLI 0.167.0](https://github.com/openai/codex/releases/tag/rust-v0.167.0)(2026年11月6日)で追加された`codex agents --no-daemon`があり、エージェントコマンドセンターを組み込みサーバー付きで開きます。通常のセッションの既定は変わりません。

## なぜこうなっているのか(システム設計の見方)

これは、ほかのツールでも見かける共有サービスの形です。すべてのターミナルがそれぞれ接続と状態を持つのではなく、1つの長く生きるプロセスがそれらを持ち、短く生きるクライアントがつなぎに行きます。

| | ターミナルごとに1プロセス | 共有のバックグラウンドサーバー |
|---|---|---|
| 次のセッションの起動時間 | 毎回フルスタート | サーバーがすでに上がっているので速い |
| セッションをまたぐ状態 | ウィンドウを閉じると失われる | サーバーが保持する |
| 使っていないときに動くもの | 何もない | サーバー |
| ディスク | CLIだけ | CLIに加えてサーバーパッケージ(ここでは338 MB) |

どちらが間違っているわけでもありません。マシンによります。バッテリーで動くノートパソコンや共有のビルドマシンは、ふつう左の列を選びます。1日に何度もセッションを開くなら、右の列を好むでしょう。

これは、[どのサーバーがあなたのリクエストを受けるか](https://systemdesignsimple.com/which-server-gets-your-request/)で説明した「1つのドア」の考え方と同じです。多くのクライアント、状態を持つ場所は1つです。

同じ「1つのプロセスが上がりっぱなし」という考え方は、[サーバーフェイルオーバー](https://systemdesignsimple.com/main-server-dies-at-3am/)の記事でも使っています。何かが常に動いているので、クライアントはコールドスタートを待たずに済みます。

## 私たちの見解

この変更についての記事の多くは、リリースノートを繰り返すだけです。抜けているのはチームの問題です。こういう既定は、一度決めて書き留めておくべきです。共有のビルドマシン、ノートパソコン、CIランナーは、それぞれ違う答えを求めます。「既定でオンだった」は、どれの理由にもなりません。

## 正直な評価

良い点: バックグラウンドサーバーは文書化されていて、フラグの名前は明確で、1つのコマンドでオンにもオフにもできます。新しい`--no-daemon`オプションは、チームが利用者に制御を渡しつつあることを示しています。

知っておくべき点: 自動起動は既定でオンで、サーバーパッケージは実際のディスクを使い(私たちのMacでは338 MB)、設定は`~/.codex/config.toml`にあり、新しいチームメンバーが最初に見る場所ではありません。

## あなたにとっての意味

- **ひとりで開発し、1日1〜2セッションの人**: 3つのチェックを1回実行してください。速い起動が大事なら既定のままにし、バックグラウンドで何も動いてほしくなければ止めてください。
- **共有マシンやCIマシン**: マシンの既定を決め、セットアップスクリプトで`codex features disable daemon_auto_start`(または`enable`)を設定し、文書化してください。
- **ディスクが少ない人**: アップグレードのあとに`~/.codex/packages/app-server-daemon/releases`を見てください。0.164.0からは、Codexは現在と直前のリリースを残すので、パッケージは2つ分を見込んでください。

両方のエージェントを使っている人は、既定を決める前に[Claude CodeとCodex CLIを一緒に使う方法](https://systemdesignsimple.com/claude-code-vs-codex-cli/)をご覧ください。
