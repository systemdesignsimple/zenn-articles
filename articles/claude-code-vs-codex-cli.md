Claude Code(Anthropic)とCodex CLI(OpenAI)は、どちらもターミナルで動くAIコーディングエージェントです。プロジェクトを読み、ファイルを編集し、コマンドを実行します。私たちは両方を毎日使っています。ここでは、それぞれが実際にどんな場面で合うか、そして大事な仕事ではなぜ互いにチェックさせているかを書きます。

これらのツールは変わるのが速いです。この比較は、2026年11月時点の私たち自身の使い方を映したものです。いまの機能は公式ドキュメントで確認してください。共通の機能は、それぞれの公式ドキュメントにあたって確かめています。「私たちにはここが合う」という部分と表は、私たちの毎日の使い方から来ています。


## 共通点
- **ターミナルエージェント:** ふつうの言葉で作業を伝えると、エージェントがコードを調べ、変更を提案し、コマンドを実行します。
- **権限とサンドボックス:** どちらも、危ない操作の前に確認を求めます([Claude Codeの権限](https://code.claude.com/docs/en/permissions)、[Codexのサンドボックス](https://learn.chatgpt.com/docs/sandboxing))。あるいは「このフォルダの中だけ書き込んでよい」のように、自分で決めた制限の中で動きます。
- **プロジェクトの指示ファイル:** どちらも、リポジトリの中の指示ファイル(たとえば[`CLAUDE.md`](https://code.claude.com/docs/en/memory)や[`AGENTS.md`](https://learn.chatgpt.com/docs/agent-configuration/agents-md))を読むので、チームのルールに沿って動きます。
- **拡張できる:** どちらもModel Context Protocol(MCP)で外部ツールにつなげます([Claude Code](https://code.claude.com/docs/en/mcp)、[Codex](https://learn.chatgpt.com/docs/extend/mcp))。

## Claude Codeが合う場面
- **長くて段取りの多い仕事:** 機能を計画し、たくさんのファイルを編集し、テストを走らせ、失敗したところを直す。作業全体の流れを保ったまま進めます。
- **ブラウザやアプリと一緒に使う仕事:** [Chrome連携](https://code.claude.com/docs/en/chrome)でウェブページを操作できます。私たちは自分のサイトのセットアップや確認に使っています。
- **作業の振り分け:** [サブエージェント](https://code.claude.com/docs/en/sub-agents)に仕事を分けて、プロジェクトのルールをきちんと守らせられます。

## Codex CLIが合う場面
- **素早い非対話の実行:** [`codex exec "..."`](https://learn.chatgpt.com/docs/developer-commands?surface=cli)はスクリプトの中で便利です。作業を渡し、最後のメッセージを`-o`でファイルに書かせれば終わりです。
- **セカンドオピニオン:** モデルの系統が違うので、気づくところも違います。
- **素材の生成:** 私たちの環境では、サムネイルやチャンネルのバナーといった画像を、パイプラインの一部として作らせています。

## 私たちのお気に入り: 互いにレビューさせる
大事なもの(スクリプト、計画、セキュリティの修正)は、1つのエージェントが作り、もう1つが独立してレビューします。

1. Claude Codeが最初のバージョンを書きます。
2. Codexがはっきりした指示で読みます。「事実の間違い、わかりにくいところ、危ない主張を見つけてください」。
3. 役に立つ指摘を取り入れ、合わないところは理由を付けて残します。

モデルが2つ違えば、間違え方も違います。だから互いのレビューは、1つのエージェントだけでは見逃す問題を拾います。人間のコードレビューと同じ考え方です。

## どちらを使うべきか
| こんなときは | こちらを |
|---|---|
| 大きくて複数ファイルにわたる作業を、段取りを追いながら進めたい | Claude Code |
| 素早いスクリプト実行や、セカンドオピニオンがほしい | Codex CLI |
| 大事な仕事で間違いをいちばん少なくしたい | 両方: 1つが書き、もう1つがレビューする |

## どちらのエージェントにも共通する実践的なコツ
- ルールは指示ファイルに書いてください。コーディングの流儀、テストを走らせるコマンド、絶対に触ってはいけないもの。
- 秘密情報はリポジトリにもプロンプトにも入れないでください。
- 変更はマージする前に毎回確認してください。エージェントは速いですが、間違えないわけではありません。
- 仕組みを信じられるようになるまでは、サンドボックスか制限付きの権限モードで動かしてください。

## 私たちの見解
私たちの毎日の仕事では、長い複数ファイルの作業はClaude Code、素早い実行とセカンドオピニオンはCodex CLIです。どちらか1つに絞る必要はありません。大事な仕事では、1つが書いて、もう1つがレビューする。この組み合わせが、間違いをいちばんよく見つけてくれます。
